# Architecture

`WardogsRadio.Core` owns configuration, the canonical Music Library (`MediaSource`, reusable `LibrarySong` cues, and ordered `StationPlaylistEntry` references), Stations, Macros, transition math, the independently testable virtual playback timeline, the pure Clip Guard / Output Health state machine, and `SystemReadinessService`. Playback receives materialized runtime song projections from those references; it does not own a second persistent cue authority. `Playback` owns provider contracts, MPV JSON IPC, endpoint meters, Windows per-app audio policy, and YouTube URL normalization. `Voicemeeter` is the only project that loads the Remote API DLL. `AudioBridgeService` owns Banana lifecycle, topology, verified mixer writes, route and microphone-device leases, recovery records, and sampled mixer telemetry. The WPF app composes that service with Windows audio endpoints, MPV, and the YouTube listening route. `Input` owns controller discovery, including HID capabilities and XInput paths. `Diagnostics` displays the shared readiness snapshot alongside advanced technical observations.

At startup, the bridge connects to a running Banana engine or requests Banana through the official Remote API and waits at most four seconds. An unsupported running edition is reported without switching the user's mixer. A stoppable bridge worker samples mixer telemetry at the fast meter cadence; the app's signal timer consumes its published snapshots and also observes the independent Windows B1 endpoint. Windows endpoint discovery refreshes every 15 seconds with a bounded scan so disconnects and returns update readiness; a staged Setup selection is retained while that endpoint remains present. The app makes up to three bounded reconnect attempts after a disconnect. An active local or YouTube game feed gets up to three separate recovery attempts; persistent failures remain Needs Attention.

Setup and macros request verified route changes from the bridge. A route lease is journaled before mutation, read back after mutation, and restored only if the current value still matches the applied value. The microphone device assignment uses a separate persisted device lease with the same external-change rule. The journal lives under `%LOCALAPPDATA%\WARDOGS Radio` and is replayed early on the next startup. A successfully saved permanent setup commits its leases; an unverified temporary change retains its recovery record. The legacy Windows-default/Voicemeeter A1 recovery record is still recognized so an interrupted session from an older candidate can be restored. Current YouTube listening targets the selected physical endpoint through a per-app audio-session policy and a separate ownership journal. A process-loopback copy feeds AUX/B1.

Output Health receives real Voicemeeter strip/B1 meter samples at the app's signal cadence. When trusted B1 telemetry and an independent game feed are available, its runtime protection gain is composed only into WARDOGS' game-music player/feed and never persists or rewrites user sliders. An explicit opt-in limiter lease can set the documented selected-strip `Strip[i].Limit` parameter only after a readback-verified capability check; the app restores its prior value when released or at clean shutdown. See [Output Health](OutputHealth.md).

The virtual timeline uses an injected clock, a stored deterministic sequence, per-video duration cache, and a cursor. It projects elapsed time across cached tracks, wraps only when loop is set, flags unknown metadata instead of inventing a position, and can be paused/resumed/navigated while inactive.
